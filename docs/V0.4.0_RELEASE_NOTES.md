# ARGUS REDLINE v0.4.0 Release Notes

**Persistent Settings and Configuration Recovery**

ARGUS REDLINE v0.4.0 adds validated local device settings, deterministic recovery, and a bounded on-device editor to both production roles while preserving the existing TEST/ACK radio protocol.

## Highlights

- Added Schema 1 settings for display timeout, display contrast, LED enable, diagnostics enable, default screen, and button feedback.
- Added exact-size, CRC-protected Schema 1 records with dual-slot generation selection, fallback repair, and no first-boot default write.
- Added a reset marker and recoverable factory-reset sequence limited to ordinary settings; recovery policy is covered by automated tests and physically prepared interruption states.
- Added a nine-item modal editor with RAM-only drafts, Save, Cancel, and two-stage Factory Reset confirmation.
- Integrated synchronous persistence only at verified role-safe points: transaction-idle on Hub and guarded post-ACK or quiet maintenance on Node.
- Preserved unsupported schemas without automatically overwriting them.

## Validation

- The pre-finalization software baseline passed 321/321 native tests.
- Hub build: 20,364 bytes RAM and 352,889 bytes flash before the identity-only version bump.
- Node build: 20,396 bytes RAM and 350,493 bytes flash before the identity-only version bump.
- Dedicated physical characterization covered absent storage, malformed records and markers, fallback repair, operation timing, reset-button persistence, and 10+ second USB power-removal persistence.
- Reset-recovery behavior was physically exercised from prepared interruption states; no active NVS write or factory-reset write sequence was physically interrupted.
- Production regression completed 70/70 matching ACKs across sequences 5–74, RSSI -45 to -43 dBm, and SNR 10.75 to 11.75 dB, with no observed retries, timeouts, malformed packets, mismatches, or unexpected resets.

## Compatibility

- Firmware identifier is `v0.4.0`.
- Protocol v0.1 remains Wire Protocol `1`.
- Existing v0.3.0 TEST/ACK packet behavior, packet format, device IDs, opcodes, retry policy, and duplicate behavior remain compatible.
- Settings are local device configuration and are not transferred over LoRa.
- Identity, provisioning, credentials, radio parameters, and protocol version are not ordinary settings.

## Deferred physical characterization

- Every timeout and contrast preset, including timeout 0, was not individually exercised on hardware.
- Diagnostics-disabled rendering and all six persisted default-screen selections were not individually exercised.
- LED-disabled gating, visible 50 ms feedback arbitration, and exact Node receive-gap duration remain unmeasured.
- Destructive NVS fault injection and a packet beginning precisely during Node standby acquisition were not performed.
- No physical interruption was introduced during an active NVS write or factory-reset write sequence; interruption recovery was exercised through prepared states.
