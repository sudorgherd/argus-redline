# ARGUS REDLINE v0.7.0 — Post-Release Endurance Soak Results

**Test date:** 2026-09-07 through 2026-09-08
**Release under test:** ARGUS REDLINE v0.7.0
**Hardware:** Two Heltec WiFi LoRa 32 V4 devices
**Roles:** Hub and Node
**Transport:** SX1262 LoRa, Wire Protocol 1
**Test type:** Unattended two-device endurance soak

## Purpose

This test was performed as post-release endurance characterization of the
ARGUS REDLINE v0.7.0 Hub/Node runtime.

The objective was to determine whether continuous autonomous Hub-to-Node
traffic could operate for approximately 24 hours without:

- device reboot,
- transaction degradation,
- retransmission growth,
- acknowledgment timeout growth,
- malformed packet accumulation,
- unexpected packet rejection,
- radio errors,
- Event persistence degradation,
- Event custody leakage, or
- unexpected Event subsystem activity.

The test was not intended as RF range characterization or adverse-channel
testing. Both devices remained in the existing bench environment for the
duration of the soak.

## Result

**PASS**

ARGUS REDLINE v0.7.0 completed a 26-hour, 36-minute, 58-second unattended
two-device endurance soak with:

- continuous uptime on both devices,
- 28,176 successful autonomous exchanges,
- zero new retransmissions,
- zero new acknowledgment timeouts,
- zero duplicates,
- zero malformed packets,
- zero new ignored packets,
- zero radio errors,
- zero Event persistence failures,
- zero Event storage corruption,
- zero unexpected Event activity, and
- no observed reboot or runtime reset.

Within the tested bench environment, no endurance-related runtime,
transaction, radio, or persistence failure was observed.

## Known Diagnostic Issue

Separate analysis performed before this soak identified a Node diagnostic
accounting defect affecting Event admission ACK handling.

A valid Event admission ACK is correctly consumed by the Event delivery
controller, but the packet subsequently continues into the ordinary COMMAND
evaluation path. Because an ACK is not a COMMAND, that second path increments
`ignoredPackets` and records `PACKET_IGNORED`.

Previous characterization showed an exact correspondence between decoded and
matched Event admission ACKs and the Node ignored-packet count.

This defect:

- does not invalidate the endurance soak,
- did not generate additional ignored packets during the soak,
- does not currently indicate Event delivery failure, and
- should be corrected in a maintenance release or subsequent development
  revision.

## Scope and Limitations

This result demonstrates sustained operation under the specific two-device
bench configuration used for the test.

It does not independently establish:

- long-range RF performance,
- interference tolerance,
- adverse-channel behavior,
- multi-Node behavior,
- authenticated transport behavior,
- routing or repeater behavior, or
- operation outside the currently supported v0.7.0 architecture.

Those capabilities remain outside the scope of this soak and, where
applicable, outside the scope of v0.7.0.
