# ARGUS REDLINE v0.4.0 Storage Characterization

**Step:** 7 — Hardware storage characterization  
**Branch:** `v0.4.0-persistent-settings`  
**Hardware:** Heltec WiFi LoRa 32 V4.3  
**Hub/TX:** COM4  
**Node/RX:** COM5  
**Production behavior integrated:** No; Step 8 was not started.

## Scope and evidence rules

This record separates direct hardware observations from prepared recovery
states, automated software validation, and deferred coverage. A prepared NVS
state is not described as a physical interruption. Host build/upload time is
not storage-operation timing. Only results reported from the physical boards
are treated as hardware evidence.

The temporary Hub probe was removed after characterization. Normal `tx`
firmware was restored to COM4; normal `rx` firmware remained on COM5. No probe
or production command globally erased NVS or cleared a namespace. Mutations
were limited to namespace `redline` and keys `cfg_a`, `cfg_b`, and `rst_pend`.

### Reset and complete-power persistence

The prepared persistent state was Slot A generation 42 with exact bytes
`524C4346010018002A0000007800400407000000E1FBA206` and `rst_pend=true`.

After pressing RST and reconnecting USB serial, Slot A remained `OK` with
identical bytes (3,057 us), and the marker remained `OK`, value 1 (785 us).

After physically unplugging Hub/TX USB for at least 10 seconds and reconnecting,
Slot A again remained `OK` with identical generation-42 bytes (3,063 us), and
the marker remained `OK`, value 1 (784 us). This was a real complete-power
removal test, not a simulated interruption.

### Adapter/manager fallback and repair

The Hub contained:

- `cfg_a`: valid Schema 1 generation 10,
  `524C4346010018000A0000003C00800407000000BAF2ACA2`;
- `cfg_b`: physically stored truncated 12-byte record,
  `524C4346010018000B000000`;
- `rst_pend`: absent.

The corrected adapter returned `MALFORMED` for the truncated slot. Two
read-only loads selected Slot A with `LOADED_FALLBACK_SLOT`, generation 10,
timeout 60, contrast 128, repair pending, and unsupported false. Durations were
5,525 us and 5,378 us. Repeated fallback proved load did not perform a repair
write and did not remove the malformed slot.

The explicit repair command then observed:

| Operation | Result | Duration |
|---|---|---:|
| Initial fallback load | `LOADED_FALLBACK_SLOT`, A, generation 10, repair pending | 5,520 us |
| Verified inactive-slot save | `SAVED`, target B, generation 11, repair clear | 7,495 us |
| Read Slot A | `OK`, 24 bytes, valid generation 10 | 2,949 us |
| Read Slot B | `OK`, 24 bytes, valid generation 11 | 2,934 us |
| Final load | `LOADED`, B, generation 11, repair clear | 6,057 us |

Post-repair bytes were:

- Slot A: `524C4346010018000A0000003C00800407000000BAF2ACA2`;
- Slot B: `524C4346010018000B0000003C00800407000000D5BE0939`.

This directly proves malformed inactive storage is not classified as storage
unavailability, valid fallback selection does not mix fields, repair writes
the inactive slot through the verified save path, generation advances 10 to
11, and the subsequent load is canonical. `rst_pend` was not touched.

### Production radio after probe restoration

With production `tx` restored on COM4 and production `rx` on COM5, two captures
contained 38/38 matching TEST/ACK exchanges: sequences 8–11 and 22–55. There
were no retries, ACK timeouts, malformed packets, watchdog messages, or resets.
RSSI ranged from -46 to -43 dBm and SNR from 10.0 to 12.0 dB.

This proves normal production radio behavior after probe restoration. It does
not prove concurrent storage/radio safety.

## Prepared/simulated reset interruption tests

These cases used deliberately prepared NVS states. Power was not physically
interrupted during an NVS operation.

| Prepared state | Recovery observation | Final state |
|---|---|---|
| A missing; B valid generation 11; marker true | `RESET_COMPLETED` in 18,043 us; active A generation 1; defaults 30/207; no repair or unsupported state | A canonical generation-1 defaults; B missing; marker missing |
| A canonical generation-1 defaults; B missing; marker true | `RESET_COMPLETED` in 17,061 us; active A generation 1; defaults 30/207; no repair or unsupported state | Marker missing |
| A canonical generation-1 defaults; B missing; marker still true | `RESET_COMPLETED` in 17,740 us; active A generation 1; defaults 30/207; no repair or unsupported state | Marker missing |

The canonical defaults record observed in Slot A was
`524C434601001800010000001E00CF0003000000B1BA81EC`.
Together the cases prove recovery when either removal was already complete,
recovery when the canonical write was already complete, idempotent recreation
of canonical defaults, and marker removal after verified completion.

## Hardware-discovered defects and fixes

1. The ESP32 adapter originally returned `StoreResult::ERROR` for a stored slot
   with a non-24-byte length. The manager treated every non-`OK`/non-`MISSING`
   read as unavailable, so valid A plus truncated B incorrectly produced
   `STORAGE_UNAVAILABLE`. `StoreResult::MALFORMED` now explicitly represents
   wrong-type or wrong-size stored slot data; the manager classifies it as a
   corrupt slot while preserving genuine access failures as unavailable.
2. An equal-settings save originally returned `UNCHANGED` even when fallback
   load had set `repairPending`. It now uses the existing verified inactive-slot
   commit path when repair is pending. Ordinary unchanged saves remain
   write-free.

Exact-size write enforcement, bounded 24-byte reads, missing-namespace behavior,
unsupported-schema preservation, and codec-owned CRC/schema validation remain
unchanged.

unsupported-schema preservation, and fallback repair followed by canonical
reload.

## Deferred and unproven coverage

- Node/RX duplicate storage characterization was deferred.
- Live storage operations during active production radio traffic were deferred.
- Concurrent storage/radio safety and role-safe automatic-repair timing remain
  unproven; the post-restoration radio regression is not a substitute.
- Physical interruption during an actual NVS write/save was not performed.
- Physical interruption during an actual factory-reset write sequence was not
  performed; the reset interruption cases used prepared states.
- Physical namespace-isolation mutation beyond the source/API scope audit was
  not performed.

These deferred items are remaining Step 7 hardware coverage, not blockers for
preserving the completed adapter/manager fixes. They remain integration risks
for later approval of concurrent persistence and role-safe repair behavior.
