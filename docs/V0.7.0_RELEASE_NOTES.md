# ARGUS REDLINE v0.7.0 Release Notes

**Node-Originated Events and Reliable Delivery**

ARGUS REDLINE v0.7.0 adds bounded, durable Node-originated Event delivery to
the existing direct one-Hub/one-Node architecture. It preserves Wire Protocol
1 and the v0.6 structured command path while adding Host Protocol 0.2 Event
polling, consumption, and diagnostics with Host Protocol 0.1 compatibility.

## Highlights

- Added persistent eight-slot Node Event custody with durable identity,
  strict FIFO delivery, five committed attempts, bounded backoff,
  powered-runtime lifetime accounting, checkpoint/reboot debit, and fail-closed
  storage behavior.
- Added persistent eight-slot Hub admission with exact Event deduplication,
  monotonic admission ordinals, durable ACTIVE/CONSUMED states, and
  commit-before-ADMITTED behavior.
- Added Wire Protocol 1 `EVENT=0x05` as an additive packet type without changing
  the six-byte header or 32-byte packet maximum.
- Added BUTTON, SENSOR_THRESHOLD, and MANUAL_CHECK_IN Event families. No panic
  or duress workflow is introduced.
- Added Host Protocol 0.2 `POLL_EVENTS` and `CONSUME_EVENT`: polling is
  non-destructive, consumption is durable, and retrying consumption is
  idempotent while its proof remains.
- Added bounded read-only Event diagnostics to the Host reference tool and a
  dedicated Event Diagnostics OLED screen. Diagnostic reads do not create,
  acknowledge, retry, consume, or otherwise mutate Events.
- Added a Linux Host transport adapter that atomically clears DTR/RTS during
  USB CDC open and avoids the ESP32-S3 reset-triggering intermediate control
  state observed during qualification.
- Preserved structured COMMAND/ACK/RESPONSE behavior, the autonomous legacy
  TEST/ACK transaction, Configuration Schema 1, and HELTEC_V4 hardware scope.

## Qualification-discovered repairs

Physical qualification exposed and cleared two release-blocking integration
defects:

1. A new Node Event could inherit volatile lifetime timing from a previous
   occupant of the same storage slot. The repaired tracked-creation boundary
   initializes only the newly durably enqueued record using a fresh policy
   timestamp and preserves existing FIFO, lifetime, retry, checkpoint, and
   reboot-debit semantics.
2. Hub structured COMMAND traffic did not participate in the existing radio
   arbiter. Production now acquires and releases the existing COMMAND ownership
   states at the correct boundaries, preserving Event-ACK preemption and receive
   restoration. The physical interleaved-PING rerun passed in 0.716341 seconds
   during active Event/capacity traffic.

The campaign also integrated the already-designed terminal FAILED/EXPIRED
reclamation path after physical diagnostics showed terminal records retaining
Node custody slots.

## Compatibility

- Firmware release: `v0.7.0`.
- Host Protocol: developmental `0.2`, with minor-1 compatibility retained.
- Wire Protocol: `1`.
- Configuration Schema: `1`.
- Hardware profile: `HELTEC_V4`.
- Wire packet maximum remains 32 bytes.
- `EVENT` is an additive Wire Protocol 1 packet type; existing numeric values
  and COMMAND/ACK/RESPONSE/TEST behavior remain preserved.
- Host request IDs remain distinct from Event identity
  (`Source_Device_ID + Event_Epoch + Event_ID`).
- Event persistence is separate from Configuration Schema 1 storage.

## Physical-qualification limitations

Three selective response-loss boundaries could not be induced legitimately
with the existing production hardware/test surfaces:

- Scenario 3: suppress only the admission ACK after durable Hub admission;
- Scenario 6: reboot the Hub precisely after admission commit while suppressing
  that admission ACK; and
- Scenario 10: suppress only the Host consume response after durable consume.

No physical PASS is claimed for those three boundaries. Deterministic/native
fault-injection tests remain authoritative. Precise physical torn-write timing
is likewise a recorded limitation covered by native storage fault injection.

Scenario 2 passed with a procedural limitation: the one-shot helper stopped
after an operator reconnect deadline was missed, but manual Hub restoration
showed the same retained Event complete its intended retry/backoff path and
admit on attempt 5 with no firmware fault.

## Security disposition

Wire Protocol 1 remains unauthenticated and unencrypted. Event identities,
CRCs, retry limits, and persistent duplicate state improve reliability; they
are not cryptographic authentication, confidentiality, or authenticated replay
protection. Production unauthenticated remote side-effect authority remains
restricted. F-02 peer authentication, F-03 authentication-first governance,
and F-04 authenticated persistent freshness/replay protection remain open.

Host Protocol 0.2 does not provide cryptographic user identity merely because
a computer is connected by USB. RF jamming protection is not provided. ARGUS
REDLINE remains experimental and is not suitable for life-safety reliance.

## Known scope limits

- One Hub and one Node remain the physically qualified topology.
- Persistent device identity and controlled provisioning are not implemented.
- Authenticated/encrypted RF transport is not implemented.
- Stable multi-client Host service/API behavior remains a later milestone.
- General opaque application transport, repeaters, routing, and mesh are not
  implemented.
- Production panic/duress semantics are not implemented.
