## 1. Purpose

This brief translates the frozen v0.7.0 designs into ordered source changes,
tests, build gates, bench integration, physical qualification, and release
closeout. It is not authority to redesign Event identity, persistence, Wire or
Host bytes, custody, expiry, retry, or arbitration.

Each stage is a reviewable implementation batch. A failure stops advancement
and is fixed at its owning layer. Codex sessions SHOULD implement one narrow
batch at a time; routine test/build/repository/release operations may be run
manually outside those sessions.

Stages 13–18 remain incomplete. In particular, the v0.7.0 Python Host reference
update, full regression/build gates, bench integration, physical qualification,
release closeout, and firmware-version promotion have not begun or completed as
applicable. The current released firmware remains v0.6.0.

## 2. Frozen Design Inputs

Implementation MUST preserve:

- identity `Source_Device_ID + Event_Epoch:uint32 + Event_ID:uint32`;
- persistent Node custody: eight dual-copy logical slots, exact 56-byte records,
  separate Event persistence domain, strict `(Event_Epoch, Event_ID)` FIFO;
- durable identity high-water reservation in blocks of 32;
- five committed delivery attempts, write-ahead before RF start;
- powered-runtime lifetime, 60-second checkpoint, and 60-second reboot debit;
- `PacketType::EVENT=0x05` as an additive Wire Protocol 1 extension;
- the exact 14..26-byte Event payload and nine-byte Event admission ACK;
- only `BUTTON=0x40`, `SENSOR_THRESHOLD=0x41`, and
  `MANUAL_CHECK_IN=0x44` in the v0.7 Event-family registry;
- persistent Hub custody: eight dual-copy logical slots, exact 56-byte records,
  persistent admission ordinal, ACTIVE/CONSUMED exact deduplication, and
  commit-before-ADMITTED;
- the intentional Node+Hub dual-custody handoff window;
- Host Protocol 0.2 category `EVENT=0x05`, `POLL_EVENTS=0x29`,
  `CONSUME_EVENT=0x2A`, 29-byte Host Event record, and nine-byte identity;
- Host-initiated polling, non-destructive POLL, explicit durable CONSUME, one
  active Host operation, one volatile retained completion, and true minor-1
  compatibility; and
- one-Hub/one-Node HELTEC_V4 physical scope.

Wire Protocol 1 remains unauthenticated. Event IDs and persistent duplicate
state are reliability mechanisms, CRCs detect corruption only, and F-02,
F-03, and F-04 remain open.

## 4. Implementation Principles

Implementation proceeds outward:

```text
pure Wire/persistent codecs
-> durable metadata and stores
-> pure Node/Hub state machines
-> Host 0.2 codec and local service
-> RadioLib/runtime integration
-> producers, diagnostics, UI
-> full regression and production builds
-> bench and physical qualification
```

Rules:

- explicit codecs serialize every external/persistent byte; never serialize a
  native struct;
- fixed arrays and compile-time bounds replace dynamic queues/containers;
- storage adapters perform NVS access; state machines never call Preferences;
- state machines receive time, entropy, storage results, and transport events
  as inputs so native tests can be deterministic;
- `src-tx/main.cpp` and `src-rx/main.cpp` orchestrate focused modules and do not
  absorb Event codecs, stores, or lifecycle policy;
- only foreground integration touches RadioLib, NVS, OLED, USB CDC, buttons,
  or capability hardware; ISR remains flag-only;
- no stage advances on a normalized/ignored failure; and
- design-authority changes require separate documentation review, not an
  implementation shortcut.

## 7. Stage 1 — Wire Event Codec and Registries

Add EVENT to `redline_protocol.h` and implement `event_protocol.h` with exact
identity/envelope/family/admission ACK codecs. Common packet decode accepts
0x05 without weakening existing type validation. Family codecs freeze only
BUTTON, SENSOR_THRESHOLD, and MANUAL_CHECK_IN.

The family value registries are closed: BUTTON accepts only PRESS `0x01`,
RELEASE `0x02`, SHORT_PRESS `0x03`, LONG_PRESS `0x04`, and VERY_LONG_PRESS
`0x05`; SENSOR_THRESHOLD accepts only the frozen value types and
UNSIGNED_32 `0x02`, SIGNED_32 `0x03`, NORMALIZED_U16 `0x04`, FIXED_Q16_16
`0x05`, and ENUM_U16 `0x06`, with CROSSED_BELOW `0x01`/CROSSED_ABOVE `0x02`
relations; MANUAL_CHECK_IN accepts only USER_REQUEST `0x01`. No
implementation-defined values are permitted.

Tests cover golden vectors, round trips, 14/26-byte payload limits, exact
32-byte maximum packet, zero identity, flags, lifetime 60..86,400, family body
length/value/type rules, unknown families, endian layout, ACK statuses,
nine-byte ACK geometry, and every correlation field. Existing packets remain
byte-identical.

**Gate:** all pure Event protocol tests and existing protocol/transaction/Wire
operation tests pass. **Stop:** no persistent or radio work begins if a codec
field, value, or vector differs from the frozen design.

## 8. Stage 2 — Persistent Event Record Codecs

The Node FREE codec uses the frozen canonical representation: it retains a

## 10. Stage 4 — Node Persistent Event Store

Implement eight logical dual-copy slots and the ESP32 adapter in a dedicated
Event namespace. Enqueue allocates identity only after range reservation,
commits/read-backs canonical QUEUED state, then reports success. Full storage is
newest-reject without identity allocation or eviction. Recovery selects copies,
validates uniqueness/content, and builds FIFO by epoch then ID.

Recovery verifies the metadata custody Source_Device_ID before reconstructing a
nonempty queue. A mismatch or unprovable context raises the explicit recovery/
configuration error, preserves records, transmits nothing, and rejects new
Event creation. Only an all-FREE store may durably adopt the current configured
Source_Device_ID.

Implement FAILED/EXPIRED terminal commits, later FREE commits, slot reuse with
new identity, and fail-closed degradation for indeterminate nonempty slots. No
radio dependency is allowed.

**Gate:** native store tests prove enqueue, capacity 8, ninth rejection,
ordering, reboot, torn writes, terminal recovery, reclamation, degradation,
nonempty identity-context mismatch, and empty-store identity adoption.
**Stop:** no delivery state machine begins before reboot custody is proven.

## 11. Stage 5 — Expiry and Durable Attempt Accounting

Add injected monotonic time and write-ahead attempt mutation to the Node store
policy. Lifetime begins at durable enqueue, decreases during all powered Node
custody, checkpoints at 60 active seconds, and debits 60 seconds at every boot
before eligibility. RAM prevents TX at zero before a pending terminal write.

An attempt is consumed when durable attempts+1 commits/read-backs before RF
start; it is not a proven emission count. `MAX_EVENT_ATTEMPTS=5` remains fixed.
Attempt and lifetime never reset on retry/reboot/backpressure.

Tests cover exact checkpoint edges, abrupt shutdown before/after checkpoint,
reboot debit, repeated short boots, `millis()` wrap, expiry in queue/wait/backoff,
write failure, five committed attempts, and terminal states.

**Gate:** deterministic native fault tests prove bounded lifetime/attempts.
**Stop:** no transport integration may compensate failed writes with volatile
state.

## 16. Stage 10 — Radio Integration and Arbitration

Only now add focused adapters and narrow main integration.

### Node (`src-rx/main.cpp`)

Keep LISTENING as idle. Event TX eligibility requires ready/listening, no ISR
flag, ACK/RESPONSE/duplicate replay/storage/render ownership absent, and READY
FIFO head. Acquire standby, recheck flag, yield to received COMMAND, persist the
attempt, then start nonblocking TX. After TX, return to receive and wait for
admission. Existing COMMAND admission, ACK-before-execute, RESPONSE, duplicate
replay, persistence safe points, Host service, UI deferral, and receive restore
remain intact.

Replace the current blocking `delay(100)` in the Node COMMAND ACK path with an
explicit nonblocking foreground timed state/deadline preserving the intended
approximately 100 ms pre-ACK ordering. No RadioLib call occurs from ISR. The
timed state keeps receive/ACK/RESPONSE/Event ownership explicit, preserves
command admission and ACK-before-execute semantics, and cannot be bypassed or
collapsed by Event eligibility.

### Hub (`src-tx/main.cpp`)

Decode EVENT alongside existing ACK/RESPONSE without allowing it to complete a
Hub COMMAND. At safe foreground points, admit/persist then transmit Event ACK.
Active Host-driven COMMAND retains priority; Event ACK work must preserve its
original overall deadline. When idle, a pending Event ACK precedes starting a
new Host COMMAND. Every radio path has one owner and restores the appropriate
receive/wait state.

Mocked integration tests cover ISR-arrival recheck, EVENT during ACK/RESPONSE
wait, Event ACK during Host work, wrong-type isolation, deadlines, TX start
failure, ACK loss, storage failure, receive restoration, and deterministic
advance through the pre-ACK deadline while UI/storage service continues and
Event TX remains ineligible.

**Gate:** production-composition native tests prove explicit ownership; existing
radio-operation bridge tests remain clean, and no blocking `delay(100)` remains
in the Node ACK path. **Stop:** no producer or hardware qualification begins on
an unresolved race, hidden concurrent RadioLib call, or blocking pre-ACK wait.

## 17. Stage 11 — Event Producers

**Implementation result:** Complete.

Implement only:

- BUTTON 0x40 from selected existing semantic `DeviceInput::ButtonEvent` values;
- SENSOR_THRESHOLD 0x41 from one deterministic simulated or explicitly safe
  capability source; and
- MANUAL_CHECK_IN 0x44 from a bounded local action.

Each calls one creation interface and handles ENQUEUED, QUEUE_FULL,
INVALID_EVENT, and STORAGE_FAILURE. Producers never allocate identity, access

and all enqueue outcomes. **Stop:** STATUS_CHANGE, DEVICE_ERROR, LOCAL_POLICY,
or any other family/opcode is prohibited in v0.7.

The implemented BUTTON source emits one Event for an eligible awake,
non-editor SHORT_PRESS and ignores its paired RELEASE. Manual check-in emits on
release of a long gesture initiated on HOME; VERY_LONG_PRESS cancels that path,
preserving settings-editor entry. Its only reason is USER_REQUEST and carries
no panic, duress, emergency, incident, or workflow meaning.

The deterministic SENSOR_THRESHOLD source observes logical capability `0x0301`
as NORMALIZED_U16 and emits CROSSED_ABOVE at `0xC000`, rearming only at or below
`0xB000` (`0x1000` hysteresis). Stable above-threshold samples do not repeat.
The production Heltec analog capability remains unavailable. Producer Events
use flags `0` and a 3600-second powered-runtime lifetime.

The bounded path is DeviceInput/capability snapshot -> producer schema and
validation -> CreationSink -> StoreCreationSink -> Node persistent Event store
-> existing delivery/radio machinery. Store STORAGE_FAILURE,
IDENTITY_FAILURE, and DEGRADED results normalize to producer-visible
STORAGE_FAILURE; producers neither receive nor allocate Event identity.

## 18. Stage 12 — Diagnostics and UI

**Implementation result:** Complete. Final Stage-12 validation passed 777/777
native tests across 35 programs; both production roles and the Hub/Node Host
transport and ESP32 Event-storage compile fixtures passed.

Add saturating counters/state with one owner per increment: enqueue accepted,
queue full, persistence failure, recovery, corruption, committed attempts,
expiry, exhaustion, Hub CAPACITY, mismatch, duplicate, new admission, exact
ADMITTED, Host poll, and durable Host consume.

Define Hub-unavailable state exactly as frozen: set after the FIFO head has a
failed admission attempt (timeout or CAPACITY); clear on exact ADMITTED or a
successful existing exchange with the configured Hub. Present queue pressure,
delivery/failure, persistence degradation, and unavailability through
`RuntimeState` snapshots and `device_ui`; UI never mutates transport/storage.

**Gate:** counter increment/saturation and snapshot presentation tests pass;
radio/UI service tests prove nonblocking observation. **Stop:** ambiguous or
double-owned counters and UI-driven transitions block integration.

`RuntimeState::EventSnapshot` is a fixed-size observational value containing 15
saturating `uint32_t` counters, Node queue count/capacity, Hub ACTIVE count,
Hub-unavailable state, and sticky runtime persistence-degraded evidence. It is
volatile, is not recovery authority, and owns no storage, radio, retry, ledger,
producer, or delivery policy.

Counter increment ownership is fixed as follows:

- Node store: enqueue accepted, queue-full rejection, persistence failure,
  recovered QUEUED Event, committed attempt, durable expiry, and durable final
  attempt exhaustion.
- Node delivery: exact ADMITTED accepted.
- Hub ledger: successful new ACTIVE admission, exact duplicate, identity/content
  mismatch, durable Host consumption, and persistence failure.
- Hub radio adapter: correlated CAPACITY response produced.
- Host Event service: newly executed POLL returning an ACTIVE Event.
- Boot integration: authoritative record-selection corruption evidence.

Counters saturate at `UINT32_MAX`; retained or idempotent operations do not
fabricate another logical diagnostic event.

unrelated/malformed/wrong responses, local TX-start failure, elapsed time, Host
activity, UI rendering, and retry start do not set or clear it.

The existing HOME screen remains snapshot-only. Node presentation shows queue
use (`EVT n/8`), Hub availability, Event-store health, and failed/expired

new UI framework or Event-specific navigation screen was introduced.
