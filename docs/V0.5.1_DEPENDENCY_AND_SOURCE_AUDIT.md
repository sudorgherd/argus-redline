## 1. Status and scope

This record closes the dependency-evidence and remaining tracked-source review work requested for v0.5.1. It does not change source, tests, dependencies, configuration, protocol behavior, or the August 14 security report. It does not finally close F-01 or declare the release ready.

Observed facts are identified as such. Applicability judgments and original-file-status reconstruction are inferences where the August 14 report did not preserve file-level evidence.

## 4. Vulnerability audit

### 4.1 Sources and method

Queries were performed on 2026-08-16 with results limited to advisories published on or before 2026-08-15. Sources included OSV exact ecosystem/package/version queries, GitHub Security Advisories, NVD/CVE cross-checks, PlatformIO and upstream security pages/release metadata, Espressif/Arduino-ESP32 advisories, the esptool repository, RadioLib's official repository/security policy, SCons security guidance, and package registry metadata.

Each match was checked for product identity, affected version, and whether the implicated feature participates in the qualified command-line build or ARGUS firmware. A zero-result automated query is not treated as proof that an ecosystem has complete advisory coverage.

Primary query records: [OSV](https://osv.dev/), [NVD](https://nvd.nist.gov/vuln/search), [GitHub Advisory Database](https://github.com/advisories), [Espressif Product Security](https://docs.espressif.com/projects/esp-product-security/en/latest/security-response.html), [Arduino-ESP32 advisories](https://github.com/espressif/arduino-esp32/security/advisories), [PlatformIO Core security](https://github.com/platformio/platformio-core/security), [RadioLib security](https://github.com/jgromes/RadioLib/security), and [SCons security](https://www.scons.org/security.html). Exact OSV records are available by appending each GHSA identifier in the table to `https://osv.dev/vulnerability/`.

## 7. Findings and dispositions

### No candidate new vulnerability

The completed source review established no materially distinct new vulnerability and no release-blocking issue.

### Informational observations

1. **README security-state drift.** `README.md` still labels the source v0.5.0 and describes duplicate identity as source/sequence/opcode, while `redline_version.h` reports v0.5.1 and `transaction_engine.h` implements payload length/byte equality. This can mislead reviewers but does not change firmware behavior. It was not edited because this task is audit evidence only.
2. **Invalid matching-ACK status terminates a Hub transaction.** `src-tx/main.cpp` passes the evaluator's matching but out-of-range ACK status to `completeAndScheduleNextTransaction` rather than continuing to wait. This is a correctness/test-coverage observation, not a distinct security finding: an RF attacker able to forge that ACK already has the F-02 capability to send a valid terminal status with equal or stronger effect. It should be considered during later protocol/transport work without duplicating F-02.
3. **Committed lab identifiers.** Qualification evidence contains board MAC/USB/COM identifiers. They are not secrets or authenticated radio identities, but are persistent lab-device identifiers.
4. **Selective first-ACK-loss remains unexecuted.** Physical cached-ACK regeneration was exercised by controlled sequence reuse; the narrower first-ACK-loss isolation scenario remains explicitly unexecuted. Native tests cover exact live retransmission.

### Known deferred findings

- **F-02:** forgeable radio metadata treated as peer identity; requires authenticated integrity and cryptographic peer identity.
- **F-03:** repeated RF commands force ACK work; requires authentication-first silent discard plus response/rate governance.
- **F-04:** captured ACK validity after sequence reuse; requires authenticated persistent freshness, replay windows, and reboot/storage-loss rules.

None was partially implemented or reclassified. The physical cached-ACK exercise also demonstrates the known F-04 sequence-reuse limitation; it is not replay protection.

## 8. Limitations

- The original exact 42-file reviewed set cannot be recovered from committed evidence; only its aggregate and named surfaces survive.
- Advisory databases have incomplete coverage for embedded registry packages, vendor toolchains, and small libraries. Absence of a match is not proof of absence.
- Package-manager content digests were unavailable, and RadioLib is unpinned in `platformio.ini`; this manifest is authoritative for the installed, qualified state, not a reproducible lockfile for an arbitrary future resolution.
- Vulnerability applicability was determined statically. No exploit execution, fuzzing, dependency upgrade, or internet-enabled clean rebuild was performed.
- PlatformIO Home/web-server vulnerabilities are outside the qualified command-line build path but remain workstation-tool considerations if that service is run.
- This record does not replace final security-report disposition or authenticated-transport design.
