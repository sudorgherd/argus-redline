## 1. Status and scope

This record documents the production dependency authority, source boundary,
qualification provenance, and final software/build evidence for ARGUS REDLINE
v0.7.0. It is not an exhaustive SBOM vulnerability scan or an independent
security audit. The project security-review record remains authoritative;
F-02, F-03, and F-04 remain open authenticated-transport requirements.

## 4. v0.7 source boundary

The release adds bounded source components for:

- Wire Event/admission codecs and the closed BUTTON, SENSOR_THRESHOLD, and
  MANUAL_CHECK_IN family registry;
- explicit Node/Hub Event persistence record codecs and ESP32 NVS adapters;
- durable Event identity allocation, Node custody, powered lifetime,
  retry/backoff, and terminal reclamation;
- persistent Hub admission, exact deduplication, ACTIVE/CONSUMED custody, and
  admission ordinals;
- Host Protocol 0.2 Event polling, idempotent consumption, Event diagnostics,
  and Python reference support;
- Node/Hub radio arbitration and receive restoration;
- Event producers and bounded UI/runtime diagnostic presentation; and
- a Linux-specific safe Host serial-open adapter that atomically clears modem
  control lines after `cdc_acm` open.

The release does not introduce a generic shell, arbitrary memory/GPIO access,
runtime plugin loading, general remote code execution, persistent provisioning,
authenticated RF transport, multi-Node orchestration, repeaters, routing,
mesh, or general opaque application transport.

## 5. Physical qualification and repair provenance

The complete chronological record is
`V0.7.0_PHYSICAL_QUALIFICATION_RESULTS.md`. Stage 16 passed on the repaired
candidate. Stage 17 passed with explicit physical-fixture limitations for
selectively suppressing the admission/consume response boundaries in
Scenarios 3, 6, and 10; deterministic/native fault injection remains
authoritative there.

Qualification discovered and cleared:

- stale volatile lifetime state when a Node storage slot was reused; and
- missing production Hub COMMAND ownership transitions during interleaved
  Event/structured traffic.

The final pre-promotion Hub rebuild exactly matched the physically qualified
Scenario-14 repair artifact. The final pre-promotion Node rebuild differed from
the physically qualified Node artifact in 75 build-metadata/digest bytes only;
no Node source changed after physical qualification. Those distinct hashes are
recorded without representing the clean rebuild as physically flashed.

These whole-image SHA-256 values identify the exact final v0.7.0 release
artifacts. Arduino/ESP32 build-generated metadata can change the embedded
application hash and final image digest on another clean build, so a whole
image fingerprint is artifact identity rather than a deterministic source
identity.

The promoted release binaries were not physically flashed. Physical behavior
was qualified on the same behavior-bearing source before the version-only
metadata promotion, following the v0.6.0 release precedent; the complete
software/build gate was then rerun after promotion.

## 8. Security disposition

v0.7.0 does not claim to close authenticated-network findings. Wire Protocol 1
still lacks cryptographic peer authentication, confidentiality, authenticated
persistent replay/freshness protection, and authentication-first RF resource
governance. Host Protocol 0.2 does not provide cryptographic user identity.
Production unauthenticated remote side-effect authority remains restricted.
RF jamming protection is not provided.

The reliability mechanisms added in this release do not change that security
boundary. No new release-blocking dependency issue was established from the
unchanged pinned dependency set and the existing project advisory evidence;
this is not a claim of exhaustive advisory coverage or absence of all
vulnerabilities.

## 9. Audit conclusion

The v0.7.0 dependency authority is explicit and unchanged from the physically
qualified framework generation. Source additions are bounded to Node-originated
Event reliability, Host 0.2 Event service/diagnostics, and qualification-driven
integration repairs. The release preserves its known security and topology
limits rather than presenting reliability as cryptographic security.
